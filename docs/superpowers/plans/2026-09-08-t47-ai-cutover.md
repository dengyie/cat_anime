# T47 AI Runtime and SQLite Cutover Implementation Plan

> **For agentic workers:** Use the executing-plans workflow and the assigned Luna workers. The task board remains GitHub #41; this file records implementation boundaries and evidence.

**Goal:** Make the sidecar the sole owner of AI requests and conversation persistence while preserving desktop chat, persona, memory, diagnostics and provider configuration.

**Architecture:** Move the existing provider and talk engines into the backend AI domain. Keep their public behavior, inject the SQLite repository into the talk store, and expose authenticated HTTP plus per-request SSE. Shell holds a read-only AI snapshot for synchronous window state and forwards requests; native window effects continue through PetService. Compile browser validation without shipping zod.

**Tech Stack:** Node HTTP/SSE, node:sqlite behind store/db.js, ESM backend, Electron Shell, React/TypeScript.

## Global Constraints

- Work in codex/issue41-t47-closure; never develop in the primary main worktree.
- Do not change 001_init.sql, the cat_anime material layout, or unrelated worktrees.
- SQLite must preserve all eight legacy state collections and full conversation keys.
- Provider keys stay in backend closure memory and Shell encrypted storage; requests, snapshots, Jobs and logs never contain them.
- Shell snapshots are read-only caches. No production AI JSON dual writer may remain.
- Native chat windows, provider ownership, streaming cancellation and interruption recovery retain their behavior.
- All new configuration stays available in Control Center.

## Task 1: SQLite repository and upgrade

**Files:** store/repositories/conversations.js, a new numbered SQL migration, a dedicated AI JSON migration/rollback module, tests/backend/conversations-repository.test.js and migration tests. Assigned worker owns these files.

**Interfaces:** createConversationsRepository({ db }) provides loadState() and commitState(state). commitState runs a synchronous transaction and changes only differing rows. The migration preserves sessions, conversations, ordered messages, personaOverrides, memories, petUtterances, memoryJobs and traces, including metadata.
